# ファイルを直す — 設計メモ

> ステータス: 2026-09-12 の決定。着手前のメモ。
> 「なぜそう決めたか」と「何を却下したか」を残すためのファイル。
> 英語版は [file-edit.md](file-edit.md)。

## 背景

右の欄にファイル一覧が立った。押すとパスが入力欄に入る ── AI に渡すにはこれでよいが、
「この1行だけ自分で直す」ができない。端末の隣に居るのだから、**読んで、少し直して、
保存する**までは手元で終わるべき。

## 貫く立場 — ここは「読む面」であって IDE ではない

**利用者は本物のコードを自分のエディタで書く。** ここが目指すのは、AI が書いたものを
その場で読み、1行直し、保存して、また AI に渡すこと。だから:

- 型チェック・補完・定義へ移動・リファクタは**作らない**。色付けと括弧とインデントまで
- 言語サーバを持たない。走らせているのは端末で、そこに本物の道具がある

この線を引かないと、際限なく IDE の再発明になる。

## 1. 何で書くか — Ace を1本だけ同梱する

素の `<textarea>` は不可。タブが効かない・自動インデントが無い・元に戻すが壊れる、で
コードの編集にならない。かといって数MBのエディタは入れられない ── 盤面は
`shell.rs` の中の1本の文字列で、バンドラが無く、**同じページをスマホが通信越しに読む**。

**Ace** (`ace-builds`, BSD-3)。中核 `ace.js` が 475KB の単一ファイルで、ビルド工程が要らない。
括弧・インデント・元に戻す・検索が最初から入っている。言語はモード1本ずつ (3〜40KB)。

- **exe に埋め込む** (`include_bytes!`)。exe の隣に置くと、欠けたとき機能が無言で死ぬ
  （[beside-exe の教訓](../../dist.list)）。埋めれば窓もスマホも同じ経路で受け取れる
- **診断ワーカーは使わない** (`useWorker: false`)。ワーカー用ファイルも配らない。
  上の「ここは読む面」がそのまま設定に落ちる
- **配色はこちらの CSS 変数で自前に定義する**。Ace のテーマファイルは配らない
- ライセンス表記を `THIRD-PARTY-NOTICES.txt` に1件足す（`conpty.dll` と同じ形）

## 2. どこで開くか — 一覧は右の欄、編集は分割したペイン

一覧は右の欄のまま。押したファイルは**画面を分割して隣のペインに出る**。幅が要るのと、
端末と並べて読めるのが本題だから。

**タブの寿命** — ここは何度も往復して決めた所:

| 状態 | 押したファイルの行き先 |
|---|---|
| エディタが1枚も無い | **使い捨てが1枚出て、以降のファイルはその1枚に差し替わる。** 設定には書かれず、閉じれば消える |
| エディタが出ている | **見ている（フォーカスのある）エディタに入る** |
| エディタはあるが出ていない | そのフォルダの1枚目を分割で出して、そこに入れる |

- **先に用意しておく必要は無い。** 押せば開く。ここを守れないなら他が全部無意味
- **押した数だけ増えない。** 使い捨ては1枚を使い回す。10 個押しても残骸は出ない
- **固定したい人は設定で置ける。** 「起動するもの: 種類 → エディタ」で1枚、フォルダに常駐。
  git パネルと同じ形。2枚並べたいときもこれ（ペインを分けて、押す前にそのペインを選ぶ）
- 行き先は**フォーカスが決める**。画面の他の場所と同じ規則で、覚え直しが要らない

作りとしては `Surface::Editor` が1つ。設定から生まれるもの (`editor` と書かれたタブ) と、
押して生まれるもの（使い捨て）は**同じ画面**で、違うのは寿命だけ。

## 3. 外から書き換わることの作法（ここが本体）

このソフトの前提は「**隣で AI が同じファイルを書き換えている**」こと。守る規則:

1. **未保存のタブは、外で変わっても読み直さない。** 下書きが消えるため。
   代わりにそのタブに「外で変わった」印を立て、読み直すか下書きを残すかを人に選ばせる。
   選択肢は知らせの上のボタン2つ（読み直す／ここの内容で上書き）。書いてある道が押せない知らせは、
   人を保存ボタンへ行かせ、そこで拒否される
2. **印が立っている間は自動保存しない。** 古い下書きで新しい内容を上書きしないため
3. **保存は引き受けられたときだけ成功と言う。** 書けなかったのに成功に見えるのが最悪
4. **読みは世代番号で古いものを捨てる。** 遅れて返ってきた読みが新しい内容を上書きしない
5. **きれいなタブにだけ「読んだ時の署名」を刻む。** 汚れたタブは古い署名を保つ
   （下書きはその古い内容から派生しているから）

## 4. AI に場所を渡す

読んでいて見つけた所を、隣の AI に「ここ」と言えること。これが端末の中にエディタがある理由。

- 渡す形は **`パス:行`**。コンパイラも grep もどの AI CLI も読む書き方で、`#L12` のような
  特定のツール専用の記法には寄せない。選択しているときは `パス:120-134`
- 出どころは2つ。**一覧から**（ファイルまるごと、今ある）と、**エディタから**
  （カーソル行、または選択範囲）
- **相対か絶対かはこちらで決める。** 入力欄の宛先タブの作業フォルダと同じなら**相対**
  （その AI はそこで走っているので、そのまま開ける）。違うフォルダ・別ホストなら**絶対**
- 入口は押せるボタン（と鍵）。**ドラッグ&ドロップは後で上乗せする** —— 指では苦しい仕草なので、
  先に両方で使える道を作る。作らない理由には使わない

## 4.1 安全

- 読み書きできるのは**そのタブの作業フォルダの中だけ**。パスは `local_under` を必ず通す
  （一覧と同じ柵）
- **大きすぎるファイルは開かない**。上限を決めて、超えたらその旨を出す
- **バイナリは開かない**。一覧が既に見分けている
- 自動保存は**既定で入れない**。保存は人が押す（Ctrl+S と保存ボタン）。
  AI が走っている隣で勝手に書き戻す機能は、事故の形が悪すぎる

## 5. 却下した案

### Monaco を載せる
**却下。** ワーカー5本と数MBの資産、そしてバンドラが要る。こちらはページが1本の文字列で、
同じページをスマホが通信越しに読む。ここで要るのは読んで少し直す面であって、
言語サービスや診断ではない ── ならば中核だけで足りる。

### 見た目編集（WYSIWYG の Markdown）
**却下。** 往復で壊れる記法が必ず出て、「この書き方のときは編集できません」という
但し書きを自分で作ることになる。Markdown も文字として直す。

### 面の種類を最初から増やす（PDF・ノートブック・CSV・画像）
**却下。** 一覧から開くのは**文字のファイルだけ**。ほかは「このファイルはここでは開けない」
と言って終わる。増やすのは、使ってから決める。
