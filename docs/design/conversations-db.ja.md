# 会話の記録（conversations.db）

> English version: [conversations-db.md](conversations-db.md).
> 今のテーブルの定義: [conversations-db.sql](conversations-db.sql)（テストが書き出します。手で直さないでください）。

AI の CLI は、会話の言葉をすべて自分の記録（JSONL のファイル）に残します。ただし、その言葉がどうやってタブに入ったかは残しません。このアプリがタブに入れた文は、窓から人が送った文も、スマホから送った文も、ほかのタブが頼んだ文も、依頼の説明も、記録の上ではすべて「ユーザー」の発言になります。CLI が出した確認に誰が答えたか、誰が止めたか、`/clear` のあとで別の会話に移ったことも、記録には残りません。

これらはすべてこのアプリを通って起きるので、アプリは知っています。アプリはそれを、状態フォルダの `conversations.db` という SQLite のファイルに書きます。右の列の「会話」パネル（`convo::read`）は、言葉を CLI の記録から読み、その横にこのファイルの事実を並べます。コードは `crates/core/src/convo/` にあります。

**会話の言葉はここに入れません。** 言葉は CLI の記録にすでにあります。写しを持つと、食い違う物がひとつ増え、貼り付けたトークンが漏れる場所もひとつ増えます。送った文については、書き出しの指紋（空白を1つに詰めた先頭 60 文字のハッシュ）だけを持ちます。記録の中からその文を見つけるには、これで足ります。

例外は AIコラボの表（`asks`・`lines`・`reactions`・`shares`）です。AIコラボは、いくつものマシンのいくつものタブを1つの画面に並べます。吹き出しのたびに各 CLI の記録を読みに行くと、吹き出しごとに往復が要ります。持つのはアプリ自身が書いた文と読んだ文だけで、ほかの行と同じ期限で消えます。

## テーブルごとの役目

| テーブル | 1行が表すもの | 記録する理由 |
|---|---|---|
| `conversations` | タブが続けた1つの会話。CLI が付けた会話の ID、アプリがそのタブをその会話で最初と最後に見た時刻、そのタブが確認なしで動く設定か | `/clear` や再開をまたいでも、1つのタブの会話を1本として読むため。確認が出ない会話では、そう言うため |
| `sends` | アプリがタブに入れた1回の文。送り主（人・ほかのタブ・依頼・自動）、どこから（この PC かリモートか）、どの道で、書き出しの指紋 | CLI の記録では、どれも人の発言として残るため |
| `spans` | タブが1つの状態にいた期間。状態が変わったときだけ書き、時計では書きません | 確認がどれだけ答えを待ったかを出すため |
| `answers` | 答え待ちを終わらせたもの。確認を出しているタブに最初に届いた入力 | CLI は何を選んだかを残しますが、誰が選んだかは残さないため |
| `stops` | 1回の停止。誰が、どこから、どの操作で（停止ボタン・Esc・依頼の停止・使用上限）、何と言われたか | CLI は「途中で止まった」としか残さないため |
| `asks` | 1回の `ask_tab`。どのタブ（または人）がどのタブに頼んだか、送った文の全文、返答の全文、どう終わったか | AIコラボの画面で、デスク全体の依頼を並べて見せるため |
| `lines` | AIコラボの吹き出し1つ。誰が言ったか、短い一言、どの依頼のものか、どうやってできたか（頼む側の一言・答える側が自分で書いた一言・答えの1文目を代わりに使った一言・単独の一言・人がタブを名指しした文・決まったこと） | どの CLI の記録にも無いため。一言は会話の中ではなくアプリに向けて言われる |
| `reactions` | 一言に付けた印1つと、付けたのは誰か（タブか人） | |
| `shares` | カード1枚。AI がほかのタブに見せたコミット・プルリクエスト・ファイル・ページ。受け付ける前に確かめてある | |
| `threads` | AI どうしの会話1つ。人がタブを名指ししたとき、または AI が別の AI に頼んだときに始まり、始めたタブの CLI の会話で決まる。依頼・一言・カードはすべてこの ID を持つ | 1つのデスクで同時に進む2つの会話を、分けて読むため |
| `thread_tabs` | 会話に加わっているタブ。名指しされた・頼んだ・頼まれた・一言を言った・カードを見せた・印を付けた | AIコラボは前に出ているタブの会話を出すため。それらを記録する書き込みと同じところで書くので、ずれない |

`meta` には `schema` の1行だけがあり、ファイルの版を表します。

状態と、`by`・`device`・`via`・`how` の列に入る語は、ただの文字列です。CHECK 制約は付けていません。どんな値が入るかは、列のコメントと `convo::db`（`By`・`Device`・`Origin`・`Stop`）に書いてあります。

## 大きくしない工夫

- 90 日（`db::KEEP_MS`）より古い行は、ファイルを開くときに消します。どの CLI も、自分の記録はそれより早く消します（Claude Code は、設定を変えなければ 30 日）。
- 記録ファイルがこの PC から消えた会話は、パネルが最初に探しに行ったときに、その会話で送った文の行と一緒に消します。
- 起動のたびに `VACUUM` はしません。消した行の場所は再利用されます。
- 1行は数百バイトです。1日に 1,000 回送っても、1日あたり約 300KB です。

## 書く側と読む側

- 書くのはアプリのメインループだけで、`convo::Log` を通します。ループから遠い場所で起きたこと（依頼が説明を打つ、スクリプトが文を送る、窓で Esc を押す）は、起きた場所で書き留め（`convo::note_sent`・`note_touched`・`note_stopped`）、ループの次の一巡で書きます。
- パネルは自分のスレッドで、読み取り専用の接続（`db::Store::open_read`）を使って読みます。WAL なので、書く側と並んで読めます。
- すべての会話の検索からは、次の関数を使えます。`Store::chain_of(record_id)` は1つのタブが続けた会話の一覧を、`read::origins(record_id, lines)` は人の発言それぞれの送り主を、`marks::all` はピンとメモを返します。

## ピンとメモはここに置かない

会話について人が書いたもの（ピンとメモ）はその人の物なので、アイデアと同じく設定と一緒に `config/conversation-marks.json` に置きます。SQLite にしないのは、設定のフォルダは別の PC と同期されることがあり、書き込み先読みのログを横に持つデータベースは、そういうフォルダで壊れるからです。

## テーブルを変える手順

このアプリのほかの SQLite のファイルと同じです（[sqlite.md](sqlite.md)）。`crates/core/src/convo/migrations/NNNN_内容.sql` を足し、`convo/db.rs` の `STEPS` に1行足します。出荷した手順は書き換えません。そのあと設計図を書き直し、差分を読みます。

```
SHIKISHA_WRITE_DOCS=1 cargo test -p shikisha-core conversations_db
```

sqlite.md の §8 のテストは `convo/db.rs` にあります。

## 動いているアプリで確かめる

`tools/debug/convo-panel.win.mjs` は、このチェックアウトのビルドを専用のフォルダで起動し、代役の Claude とシェルを置いて、窓と盤面のリモートの入口から次を確かめます。窓から送った文、リモートのページから送った文、ほかのタブが送った文、確認にリモートから答えたこと、窓での Esc、チェックボックス、検索（ツールの出力の中だけにある語）、ピン、ファイルに言葉が残っていないこと。画面の写真は `node tools/debug/shoot.mjs tools/debug/scenes/convo.mjs` で撮ります。
