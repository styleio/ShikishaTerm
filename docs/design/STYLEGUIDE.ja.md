# SHIKISHA-TERM 画面の規約

画面に見えるものを変える作業は、すべてこの1枚に従います。配置、色、文字、余白、
どの部品を使うか、どう振る舞うか、何と言うか。値そのものはコードにあります。この
ページが決めるのは「その値が何のためにあるか」と、「出す前に画面をどう採点するか」
です。英語版は [STYLEGUIDE.md](STYLEGUIDE.md)。

**役割が決まっている値を、新しく作らない。** 新しい16進の色、新しい文字サイズ、
新しい影、新しい角丸は増やしません。役割が足りないときは、先にここへ足してから
使います。

---

## 1. 正本はどこか

| 何 | どこ | 備考 |
|---|---|---|
| 色の変数 | `src/theme.rs` の `css_vars()` | 選んだ配色から起動時に書き出す。どのページも CSS 変数として読む |
| 盤面のページ（タブバー・ペイン・最下段・ダイアログ） | `src/shell.rs` | 1枚のページが窓とスマホの両方を描く |
| 設定のページ | `src/webui.rs` | 同じ変数。3つだけ古い名前（`--muted` `--accent` `--danger`） |
| トースト | `src/toast.rs` | 両方のページで共通 |
| 画面の文字 | `lang/en.json` を `lang/ja.json` が上書き | ページに直書きしない。§7 |
| 文字の決め方 | `.claude/RULES.md` の「利用者に見せる言葉」「日本語の文章」 | ここには写さない |

盤面のページは、状態が届くたびに（1秒に数回）作り直されます。そこに描くものは
作り直しに耐えること。一度作ったら、変わったところだけ触る（`dataset.said`、
`dataset.key`）。押している最中の要素を DOM から消さない。

## 2. 色の役割

色は配色の両端（背景と文字）を混ぜて作るので、明るい配色でも二つ目のパレットは
要りません。呼ぶのは役割の名前で、色の名前ではありません。

### 面

| 変数 | 役割 | 使う場所 |
|---|---|---|
| `--bg` | ページそのもの | 端末の地、ダイアログの入力欄 |
| `--panel` | ページの上に置いた面 | タブバー、最下段、カード、メニュー、吹き出し |
| `--raise` | 選ばれている・まとまっている | 選択中の行、家族の箱、お礼のカード、ダイアログのボタン |
| `--hover` | ポインタの下 | 行とメニュー項目のホバーだけ |
| `--sunk` | ページに沈めた面 | 読むだけの井戸 |
| `--tint` | 看板色に寄せた面 | 読み込み中の帯、構えたボタン |
| `--line` | 構造 | 仕切り、カードとダイアログの枠、空の棒の溝 |
| `--sel` / `--cursor` | 端末の選択と カーソル | 端末だけ。配色が名指ししていればそれを使う |
| `--panel2` / `--sys` | 設定ページの2つ目・3つ目の面 | 設定ページだけ。`--raise` より前からある名前で、新しく置く面は `--raise` を使う |

### 縁

構造の線と、押せる物の縁は別の仕事です。両方を `--line` で引いたせいで、
フォームが「文字が浮いているだけの平らな紙」に見えていました。

| 変数 | 役割 |
|---|---|
| `--line` | 構造。仕切る・囲む。静かなままでよい |
| `--edge` | 打ち込める物・押せる物の縁 |
| `--edge-hi` | その縁の、ポインタが乗っているとき |

### 文字

| 変数 | 役割 |
|---|---|
| `--text` | 読むもの |
| `--dim` | 目をやるもの。ラベル、メタ、行のフォルダ名 |
| `--faint` | コントロールの下の説明、プレースホルダー |

2段ではなく3段。ラベルとその下の説明が同じ濃さだと、読む順番が生まれません。

### 状態（意味を持つ色はこれだけ）

| 変数 | 意味 | 出てよい場所 |
|---|---|---|
| `--brand` | **注目と「答えた」**。フォーカスしたペインの下線、完了の点、選択行の縁、主ボタンの枠 | 構造の枠には使わない。状態でない文字にも使わない |
| `--live` | **作業中**。処理中の点、普通に伸びている棒、AUTO ON | |
| `--warn` | **人が要る、または残りわずか**。確認待ちの点、上限の知らせ、80% を超えた棒、リモートに遅れたフォルダ | |
| `--stop` | **止まった・危ない**。終了の点、停止ボタン、95% を超えた棒、削除 | |

状態に使った色を、その近くで飾りに使わない。青い罫線は、どこに引いても「ここから
ペイン」と読まれます。

### AI ごとの色

AI には1つずつ色があります（`--ai`。claude `#d97757`、codex `#19c37d`、gemini
`#4285f4`、deepseek `#5b7cff`、qwen `#a06bff`、aider `#e5644d`、kimi `#12b3a8`）。
タブの行では左端と名前の2か所だけ。その AI のもの（最下段の残量など）の前に名前を
出すときは、その名前だけ。点には使わない、構造の枠には使わない、状態の色と混ぜない。

### コントラスト

`--panel` や `--raise` の上の文字は `--text` か `--dim`。10px の状態色の文字は
読めません。画面は暗い配色と明るい配色の両方で確かめます（設定で名前を選べます）。
`--dim` が文字の 65% なのは、それより薄いと穏やかな配色で読めなかったからです。

## 3. 文字

面が2つ、仕事も2つ。**盤面は端末そのもの**なので、すべて `--mono`（端末の
フォント）。これがこの製品の顔です。**設定ページは読む文書であり書き込む用紙**
なので `--ui`。日本語の長い文が等幅の代替フォントに落ちると、味が出るのではなく
ただ読みにくくなります。

どちらの面でも、**人が打ち返せるもの**——自動化での呼び名、コマンド、パス、URL、
ID——は `--mono`。引用は引用の顔をしていること。

階層は大きさ・太さ・3段の文字色で作ります。3つ目の書体は足しません。

| 大きさ | 役割 | 例 |
|---|---|---|
| 14px | 端末の文字（`--fs`）、チェックボックスのラベル | |
| 13px | 用紙の本文。欄に打ち込む字、押せる行 | 入力欄、タブの行、メニュー項目 |
| 12.5px | ボタン | 設定ページのボタン全部 |
| 12px | 欄の名前、見出し、状態の1行 | フォームのラベル、最下段、家族の元の見出し |
| 11.5px | 静かな見出し、物を説明する1行 | 家族の元でないフォルダ見出し、ヒント |
| 11px | 補助 | チップ、数、コントロールの下のヒント |
| 10px | 行の下のメタ | タブが最後に言ったこと、どこにいるか（ブランチ・ポート）、見出しのブランチ札 |
| 9px | 矢印 | ▾ ▸ だけ |

太字（600）は「その物の名前を言う1行」だけ。プロジェクトの見出し、カードの題、
AI の名前。ほかは太くしない。字間 `.02em` は 11〜12px の見出しだけ。

比べる数字はそろえる: `font-variant-numeric: tabular-nums`。

## 4. 余白・角丸・影

- 行は `padding: 7px 10px; gap: 8px`。行の子は一段入る。フォルダの下のタブは
  26px、プロジェクトの下の枝はさらに 14px。
**余白は段で決まっていて、画面のすべての隙間はこの6つのどれかです。** これが
無かったせいで、ラベルとその欄の距離と、欄と次の質問の距離が同じになり、
フォームが「関係のない行の長い列」に見えていました。

| 変数 | 値 | 何と何を離すか |
|---|---|---|
| `--s1` | 4px | 1つの語の中。見出しとその後ろの「（任意）」 |
| `--s2` | 8px | ラベルとその欄。箱とその中の文 |
| `--s3` | 12px | 横に並ぶ物どうし。コントロールの内側 |
| `--s4` | 16px | カードと次のカード |
| `--s5` | 20px | 質問と次の質問。カードとダイアログの内側 |
| `--s6` | 24px | ダイアログの左右 |
| `--s7` | 32px | ページの上 |

**押せる物の高さは2つだけ。** 入力欄は **36px**、ボタンは **32px**。欄の横の
ボタンが一回り小さく見え、ボタンの列にリズムが出ます。これより低くしない——
32px の箱に文字が枠にくっついて入っている形は、15年前の管理画面の形です。

| 変数 | 値 | 何に |
|---|---|---|
| `--r-ctl` | 6px | 押す物・打ち込む物。入力欄、ボタン |
| `--r-card` | 10px | それを載せる物。カード、ダイアログ、浮くメニュー |
| `--r-chip` | 4px | それに札を付ける物。チップ、小さな札 |

棒の **3px** と最下段の札の **999px** だけが例外です。
- 影は1種類、`0 8px 24px #0007`。ページの上に浮く層（メニュー、吹き出し、
  ダイアログ）だけ。ページに置いたものに影は無い。
- 重なりの順（下から）: ペイン (3〜6) · 入力欄 (18〜19) · ペインの上の帯 (22〜26) ·
  読み返し (30) · スマホの引き出し (30) · 起動画面 (40) · 覆い (50) · 初回の吹き出し (55) ·
  メニューと切断の覆い (60)。ある段を使う。数を増やさない。

## 5. 部品

あるものを使う。新しい種類の部品を足すことは、このページを変えることです。

| 部品 | 何のため | 作り |
|---|---|---|
| **タブの行** | 動いている1つ | 点（状態）· 番号 · 名前 · 鍵 · 出力の棒。その下に、どこにいるか、次に最後に言ったこと |
| **状態の点** | そのタブが今どうなっているか | 8px の丸。**色＝どんな知らせか、塗り方＝あなたの番かどうか**。塗り＝いま誰かの番（`BUSY` `QUESTION` `DONE` `FAILED`）、輪郭だけ＝同じ知らせだが今できることは無い（`BACKGROUND` `LIMIT` `EXIT`）。輪郭は `inset 0 0 0 2px`。点滅するのは `BUSY` だけ |
| **フォルダの見出し** | タブが動く場所 | 印（四角＝プロジェクト、枝線＝枝）· 矢印 · 名前 · [ブランチ札] · [枝の数] · 遅れ · `+` |
| **家族** | プロジェクトとその枝 | `.family` の箱を `--raise` で。元は 12px/600、枝は一段入る |
| **札**（最下段） | いまの事実1つ | 文字か、棒と言葉。押して何か起きるときだけ押せる（上限の知らせ）。ほかは押せない |
| **棒** | 0〜100 の数 | 溝は `--line`、中は `--live`、80% で `--warn`、95% で `--stop`。必ず隣に言葉。何の何％で、いつ戻るか |
| **ダイアログ**（`.vbox`） | 決めごと1つ | 題 · 一文 · 項目 · 実行されるものそのまま（等幅の井戸）· 右に主ボタン1つ、上に ✕ |
| **ダイアログ**（設定・`.framed`） | 1件を直す | **頭**（題 · ✕）· **胴**（項目）· **足**（左に壊すボタン、次に保存できない理由、右にキャンセルと主ボタン）。それぞれ `--line` で仕切る |
| **ダイアログ**（選ぶ・`.picker`） | たくさんの中から場所を1つ | `.framed` と同じ頭・胴・足に、胴を**2列**（左 200px＝始める場所、右＝パンくず · 一覧）。幅 `min(760px,100%)`、胴の高さは固定（中身で窓が伸び縮みしない）。頭の下に絞り込みの欄。行は1回押すと**選ぶ**、`›` か2回押すと**入る**（スマホは `›` だけが入口）。足は「選択中のもの」· 左に**足す**ボタン · 右にキャンセルと主ボタン。印は線画、絵文字は使わない。640px 以下で左の列は上の横一列になる |
| **欄** | 打ち込むもの1つ | 名前が上（12px `--text`）· コントロール · 説明が下（11.5px `--faint`）。あいだは `--s2`、次の欄までは `--s5` |
| **囲った一覧**（`.rows`） | 同じ物が何件か | 全体を1本の枠で囲む · 行のあいだは `--line` · ホバーで `--panel2` · 行が何かを開くなら右端に `›` |
| **左の柱**（設定） | いまどこを直しているか | **看板**（頭文字の板 · 名前 · 歯車 · 右端に `▾`）· **アプリ全体設定**の1行 · その下は木。名前と歯車＝そのデスクの設定、`▾`＝別のデスクへ、全体設定＝木と入れ替えでその一覧を出す |
| **木の行** | 入れ子の1つ | `├ └ │` は行ごとに数えて出す（自分と同じ深さが後にあるか）· 折りたたみは `▾ / ▸` · 印はフォルダ＝線画（案件の色）、タブ＝点（AIの色）· 印の無い行も同じ列を空けておく |
| **一覧**（`.fmenu`） | 少数から1つ選ぶ | 浮く、角丸 10、1行に1つ、外を押せば閉じる |
| **吹き出し**（`#coach`） | 次に押す所を指す | 一文 · ✕ · 刺す先へ向いた角。画面に1つまで |
| **カード**（サイドバー） | 一度だけ聞く | 題 · 1行 · ボタン2つ（主と静か）。押したら二度と出ない |
| **トースト** | いま起きたことを言う | 流れて消える。エラーの唯一の置き場にしない |
| **呼びかけの帯**（`#ask`・`.pask`） | 台本がページ上の作業を人に頼む | 一文 · 主ボタン1つ。上辺は `--warn`（人が要る）。盤面がページの下に描き、ページの中には決して描かない＝押せるのは人だけ。台本が下げるまで残る |
| **ボタン** | する | 主＝`--brand` の塗り（1画面・1ダイアログに1つ）、並＝`--edge` の枠に `--panel2`、静か＝枠なし、壊す＝`--stop` の文字・枠なし。キャンセルと閉じるは静か。色を付けない |

**押せないボタンも、押されたら答える。** 灰色にする——薄くした看板色ではなく
灰色。薄い青はやはり青に見えます。そのうえで押下は受け取り、なぜ止まっているか
と、どうすれば解けるかを、消えない場所に書く。同時に、直すべき物へ目を運ぶ。
灰色にして押下を黙って捨てる部品は行き止まりで、利用者はどこにも行けません。

上の表で、いちばんよく破られる3つ:

- **数字を裸で置かない。** `20%` は事実ではない。`20% 使用 · 3時間45分後に回復` が
  事実。数字には必ず名前（何の数か）と、変わるものなら時刻が付く。
- **棒も裸で置かない。** 棒は数字、隣の言葉が文。
- **利用者に覚えさせる規則は、間違った規則。** 2つの物を違う書き方にしている
  （`example.com` は1つの意味、`http://example.com` は別の意味）なら、両方とも
  省略せずに書かせる。**枠の中にあるものが、そのまま照合されるもの**。

### 5.1 欄

打ち込むもの1つ。どの画面でも同じ形。

```
ラベル            12px / 500 / --text
  ↕ 8px  (--s2)
コントロール      高さ 36px、13px、--bg に 1px の --edge、角丸 6px、左右 12px
  ↕ 8px  (--s2)
説明              11.5px / --faint
  ↕ 20px (--s5)  次の欄まで
```

- 名前は**コントロールの上**。どの幅でも。左に150pxのラベル列を作ると、左右
  どちらも幅が足りなくなり、形が管理画面になります。
- **例外は表。** 同じ問いが何十行も続く画面（キーの割り当てなど）は、フォームでは
  なく表です。そこでは名前が自分の列を持ちます——目がやることは1行を読むことでは
  なく、列を上から下へ走らせて目当ての行を見つけることだからです（`.row.pair`）。
- チェックボックスだけは例外で、自分のラベルは横に並びます。箱15px、あいだ
  `--s2`、ラベル14px `--text`。関係のある2つは1行に `--s5` 空けて並べ、
  縦には積みません。
- フォーカスは `--brand` の枠**と** 22% の3pxリング。枠を太くするだけにしない
  ——タブで送るたびに箱の大きさが変わります。
- 非活性は `--panel2` に `--dim` の文字、`cursor: not-allowed`。
- 間違っている欄は `--warn` の枠にし、理由をその**すぐ下**に `--warn` の箱で
  出す（内側 `--s2` `--s3`、角丸6px、背景は9%、枠は35%）。

### 5.2 ダイアログ

```
┌─────────────────────────────────────────┐
│ 頭   16px 20px   題 13.5/600 ・ ✕        │   ← 下に 1px の --line
│ 胴   20px        欄                      │
│ 足   12px 20px   [壊す]              …   │   ← 上に 1px の --line
│                  [止まっている理由]      │
│                  [キャンセル] [主ボタン] │
└─────────────────────────────────────────┘
  幅 min(560px, 100%) · 角丸 10px · --panel に 1px の --line
  影 0 8px 24px #0007 · 窓の上から 56px
```

- **Esc で閉じ、1行の欄での Enter は主ボタン。** 背景を押せば閉じる。ただし
  押し始めが中なら閉じない（文字を選んで枠の外で指を離すのは取り消しではない）。
- フォーカスは最初に打ち込むところへ。空の欄の1つ目か、その人が直しに来た欄。

### 5.3 ボタンの位置

決めごとは1つ。画面ごとに覚え直させない。

| どこ | 保存・確定 | 壊す | キャンセル |
|---|---|---|---|
| ページ（設定） | 上端の帯の右上。ページ全体で1つ | **最後のカードの外**に自分の行を作り、`--stop` の文字・枠なし | 無し。ページは閉じて出る |
| ダイアログ | 足の右端。`--brand` の塗り | 足の**左端** | 足の、主ボタンの隣。静か |
| 一覧の行 | 無し。行がダイアログを開く | そのダイアログの中 | 無し |

1つの画面に主ボタンを2つ置かない。ダイアログが開いているとき、ページの保存は
覆いの向こう側で、いま話題になっているボタンではありません。

足の左端に置いてよいのは、**壊すボタン**か、**ダイアログの中身に足すボタン**
（選ぶダイアログの「新規フォルダ作成」）の**どちらか1つ**。どちらも主の操作から
遠ざけておきたい物です。足すボタンは並（`--edge` の枠）で、壊すボタンと同じ
`--stop` の文字にはしない。1つのダイアログに両方は置かない。

### 5.4 押せないボタン

**灰色にして、それでも答える。** `disabled` にはしない。押下は受け取り、理由を
言う。

- 見た目は非活性: `--panel2`、`--line` の枠、`--faint` の文字、
  `cursor: not-allowed`、ホバーで変化しない。看板色を薄くしたものは使わない
  ——薄い青はやはり青に見えます。
- 押されたら、消えない場所に理由を書く: `--warn`、11.5px、足のボタンの上に
  1行。「保存できません:」のように**起きなかったこと**から始め、**どうすれば
  解けるか**で終える。
- 同時に、直すべき物に 6px の `--warn` リングを 0.9 秒 × 2回出し、そこへ
  画面を送る。
- 理由は現状に追随する。止めている物が別の物に変われば、出ている文もその場で
  変わり、止める物が無くなれば消える。

### 5.5 記録の一覧

```
.rows        全体を 1px の --line で囲む、角丸 6px、行のあいだも 1px の --line
  行         10px 12px、間隔 12px、ホバーで --panel2、行全体でダイアログを開く
             名前（等幅・132px）· チップ · 何であるか（--dim・あふれは …）
             · 右端に件数（tabular-nums）· ›
```

`›` が入口の合図で、編集ボタンは置きません。ホバーしないと分からない行はスマホで
分からない行なので、スマホでは行が畳まれます——名前が1行を取り、残りがその下に
続きます。

## 6. 動き

永久に動くものを置かない。窓の中の滑らかなアニメは、動いている間ずっと1コアの
2割を食います。許すのは `step-end` の点滅2つ。処理中の点と、次に押す1か所の
パルス。開閉は一段で大きさが変わってよい。ページが読めるなら「動きを減らす」の
設定に従う。

## 7. 言葉

決めごとは `.claude/RULES.md`。画面で一番よく滑るところの検査:

- ラベルは名詞（「ここで起動」）、ボタンは動詞（「作る」）、ヒントは「何が起きるか」で、
  「なぜそうしているか」ではない。
- 開発の言葉を画面に出さない。フック、プリミティブ、プロトコル、トークン。worktree は
  製品では「並行開発」で、git の語は括弧で一度だけ。
- 「〜してください（お願い）」「簡単に」「〜できます」「任意」「無視して構いません」を
  書かない。
- コードがやっていないことを言わない。「作りました」「見つけました」「送りました」は
  結果があってから。途中は「何をしているか」を書く。
- 文字はすべて `lang/en.json` から `T[...]` / `t()` で。日本語は `lang/ja.json` に、
  日本語の読者向けに書く（訳さない）。常用漢字だけ。

## 8. 窓とスマホ

盤面のページは窓でもスマホでもあります。どの部品も指で使えること。ホバーでしか
届かないものを置かない、22px より小さい押す物を置かない、メニューはタップで開く。
窓でできることはスマホでもできる。例外は「開く先がこの PC の中」のときだけで、その
ときスマホには素のリンクか何も無いかで、理由をコメントに書く。

## 9. 画面の採点

画面を変えたセッションは、終わる前にスクリーンショットを撮り、この表で採点します。
効き目の大きい直しを3つ先に挙げ、直してから `/announce` に渡します。

**それぞれに答える。「いいえ」は直すことであって、書き残すことではない。**

1. **初見で読める。** この製品を見たことがない人が、画面の言葉と数字を全部分かるか。
   数字には名前が、変わるものには時刻が付いているか。
2. **押す所は1つ。** 主の操作が、位置と `--brand` の塗りで一目で分かり、ほかは静かか。
   押せないボタンは灰色で、押したら理由を言い、直す先を指しているか（§5.4）。
3. **2回で終わる。** よくある道が、1〜2回の操作で終わるか（プログラムが既に十分
   知っているなら）。
4. **フォーカスとキー。** ダイアログで、Enter が主の操作になる場所にフォーカスが
   あり、Esc が静かに戻るか。
5. **状態の色は状態だけ。** 青は注目と完了、緑は作業中、黄は人が要る・残りわずか、
   赤は停止。飾りに使っていないか。
6. **格子。** 行と列がそろい、点が1本の列に並び、比べる数字は右ぞろえか。
7. **言葉。** ラベルは名詞、ボタンは動詞、開発の言葉なし、埋め草なし、やっていない
   ことを言っていない。日本語の段落は `natural-japanese` の検査を通したか。
8. **空と失敗。** まだ何も無いとき、次に押す所を言っているか。失敗したとき、読んで
   直せる場所にエラーが残り、直す先が別なら案内があるか。
9. **兄弟。** 隣の部品と1つの設計に見えるか（同じ大きさ、同じ角丸、同じ行為に同じ言葉）。
   欄・ダイアログ・一覧は §5.1〜5.5 の寸法どおりか。保存と削除は §5.3 の位置か。
   隙間は `--s1`〜`--s7` のどれかで、途中の数字を書いていないか。
10. **両方の配色、両方の面。** 明るい配色でも、スマホ幅で指でも、正しいか。
11. **永久に動くものが無い。**
12. **作り直しに耐える。** 1秒に数回作り直されても、ちらつかず、押し損ねず、開いた
    一覧が状態の到着で閉じないか。

書き方: **直す3つ** · **引っかかり**（要素ごと）· **直したこと** · **残したことと理由**。
