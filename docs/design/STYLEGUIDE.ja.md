# SHIKISHA-TERM 画面の規約

画面に見えるものを変える作業は、すべてこの1枚に従います。配置、色、文字、余白、
どの部品を使うか、どう振る舞うか、何と言うか。値そのものはコードにあります。この
ページが決めるのは「その値が何のためにあるか」と、「出す前に画面をどう採点するか」
です。英語版は [STYLEGUIDE.md](STYLEGUIDE.md)。

**役割が決まっている値を、新しく作らない。** 新しい16進の色、新しい文字サイズ、
新しい影、新しい角丸は増やしません。役割が足りないときは、先にここへ足してから
使います。

---

## 1. 正本はどこか

| 何 | どこ | 備考 |
|---|---|---|
| 色の変数 | `src/theme.rs` の `css_vars()` | 選んだ配色から起動時に書き出す。どのページも CSS 変数として読む |
| 盤面のページ（タブバー・ペイン・最下段・ダイアログ） | `src/shell.rs` | 1枚のページが窓とスマホの両方を描く |
| 設定のページ | `src/webui.rs` | 同じ変数。3つだけ古い名前（`--muted` `--accent` `--danger`） |
| トースト | `src/toast.rs` | 両方のページで共通 |
| 画面の文字 | `lang/en.json` を `lang/ja.json` が上書き | ページに直書きしない。§7 |
| 文字の決め方 | `.claude/RULES.md` の「利用者に見せる言葉」「日本語の文章」 | ここには写さない |

盤面のページは、状態が届くたびに（1秒に数回）作り直されます。そこに描くものは
作り直しに耐えること。一度作ったら、変わったところだけ触る（`dataset.said`、
`dataset.key`）。押している最中の要素を DOM から消さない。

## 2. 色の役割

色は配色の両端（背景と文字）を混ぜて作るので、明るい配色でも二つ目のパレットは
要りません。呼ぶのは役割の名前で、色の名前ではありません。

### 面

| 変数 | 役割 | 使う場所 |
|---|---|---|
| `--bg` | ページそのもの | 端末の地、ダイアログの入力欄 |
| `--panel` | ページの上に置いた面 | タブバー、最下段、カード、メニュー、吹き出し |
| `--raise` | 選ばれている・まとまっている | 選択中の行、家族の箱、お礼のカード、ダイアログのボタン |
| `--hover` | ポインタの下 | 行とメニュー項目のホバーだけ |
| `--sunk` | ページに沈めた面 | 読むだけの井戸 |
| `--tint` | 看板色に寄せた面 | 読み込み中の帯、構えたボタン |
| `--line` | 構造 | 枠、罫線、仕切り、空の棒の溝、すべて |
| `--sel` / `--cursor` | 端末の選択と カーソル | 端末だけ。配色が名指ししていればそれを使う |
| `--panel2` / `--sys` | 設定ページの2つ目・3つ目の面 | 設定ページだけ。`--raise` より前からある名前で、新しく置く面は `--raise` を使う |

### 文字

| 変数 | 役割 |
|---|---|
| `--text` | 読むもの |
| `--dim` | 目をやるもの。ラベル、補助、ヒント、行のフォルダ名 |

### 状態（意味を持つ色はこれだけ）

| 変数 | 意味 | 出てよい場所 |
|---|---|---|
| `--brand` | **注目と「答えた」**。フォーカスしたペインの下線、完了の点、選択行の縁、主ボタンの枠 | 構造の枠には使わない。状態でない文字にも使わない |
| `--live` | **作業中**。処理中の点、普通に伸びている棒、AUTO ON | |
| `--warn` | **人が要る、または残りわずか**。確認待ちの点、上限の知らせ、80% を超えた棒、リモートに遅れたフォルダ | |
| `--stop` | **止まった・危ない**。終了の点、停止ボタン、95% を超えた棒、削除 | |

状態に使った色を、その近くで飾りに使わない。青い罫線は、どこに引いても「ここから
ペイン」と読まれます。

### AI ごとの色

AI には1つずつ色があります（`--ai`。claude `#d97757`、codex `#19c37d`、gemini
`#4285f4`、deepseek `#5b7cff`、qwen `#a06bff`、aider `#e5644d`、kimi `#12b3a8`）。
タブの行では左端と名前の2か所だけ。その AI のもの（最下段の残量など）の前に名前を
出すときは、その名前だけ。点には使わない、構造の枠には使わない、状態の色と混ぜない。

### コントラスト

`--panel` や `--raise` の上の文字は `--text` か `--dim`。10px の状態色の文字は
読めません。画面は暗い配色と明るい配色の両方で確かめます（設定で名前を選べます）。
`--dim` が文字の 65% なのは、それより薄いと穏やかな配色で読めなかったからです。

## 3. 文字

書体は1つ、`--mono`（端末のフォント）。両方のページで、どこでも。これがこの
製品の顔で、プロポーショナル体が1か所でも混じれば別の製品になります。階層は
大きさと太さと `--dim` で作ります。

| 大きさ | 役割 | 例 |
|---|---|---|
| 14px | ページの本文 | ダイアログの入力、端末の文字（`--fs`） |
| 13px | 押せる行 | タブの行、ダイアログのボタン、メニュー項目 |
| 12px | 見出し、または状態の1行 | 最下段、家族の元の見出し、設定のカード題 |
| 11.5px | 静かな見出し | 家族の元でないフォルダ見出し、ダイアログのヒント |
| 11px | 補助 | チップ、数、コントロールの下のヒント |
| 10px | 行の下のメタ | タブが最後に言ったこと、どこにいるか（ブランチ・ポート）、見出しのブランチ札 |
| 9px | 矢印 | ▾ ▸ だけ |

太字（600）は「その物の名前を言う1行」だけ。プロジェクトの見出し、カードの題、
AI の名前。ほかは太くしない。字間 `.02em` は 11〜12px の見出しだけ。

比べる数字はそろえる: `font-variant-numeric: tabular-nums`。

## 4. 余白・角丸・影

- 行は `padding: 7px 10px; gap: 8px`。行の子は一段入る。フォルダの下のタブは
  26px、プロジェクトの下の枝はさらに 14px。
- 角丸: ページに置くもの（ダイアログ、カード、入力欄、ボタン）は **8px**、浮く
  メニューと吹き出しは **10px**、チップと小さな札は **4px**、棒は **3px**、
  **999px** は最下段の札だけ。
- 影は1種類、`0 8px 24px #0007`。ページの上に浮く層（メニュー、吹き出し、
  ダイアログ）だけ。ページに置いたものに影は無い。
- 重なりの順（下から）: ペイン (3〜6) · 入力欄 (18〜19) · ペインの上の帯 (22〜26) ·
  読み返し (30) · スマホの引き出し (30) · 起動画面 (40) · 覆い (50) · 初回の吹き出し (55) ·
  メニューと切断の覆い (60)。ある段を使う。数を増やさない。

## 5. 部品

あるものを使う。新しい種類の部品を足すことは、このページを変えることです。

| 部品 | 何のため | 作り |
|---|---|---|
| **タブの行** | 動いている1つ | 点（状態）· 番号 · 名前 · 鍵 · 出力の棒。その下に、どこにいるか、次に最後に言ったこと |
| **フォルダの見出し** | タブが動く場所 | 印（四角＝プロジェクト、枝線＝枝）· 矢印 · 名前 · [ブランチ札] · [枝の数] · 遅れ · `+` |
| **家族** | プロジェクトとその枝 | `.family` の箱を `--raise` で。元は 12px/600、枝は一段入る |
| **札**（最下段） | いまの事実1つ | 文字か、棒と言葉。押して何か起きるときだけ押せる（上限の知らせ）。ほかは押せない |
| **棒** | 0〜100 の数 | 溝は `--line`、中は `--live`、80% で `--warn`、95% で `--stop`。必ず隣に言葉。何の何％で、いつ戻るか |
| **ダイアログ**（`.vbox`） | 決めごと1つ | 題 · 一文 · 項目 · 実行されるものそのまま（等幅の井戸）· 右に主ボタン1つ、上に ✕ |
| **一覧**（`.fmenu`） | 少数から1つ選ぶ | 浮く、角丸 10、1行に1つ、外を押せば閉じる |
| **吹き出し**（`#coach`） | 次に押す所を指す | 一文 · ✕ · 刺す先へ向いた角。画面に1つまで |
| **カード**（サイドバー） | 一度だけ聞く | 題 · 1行 · ボタン2つ（主と静か）。押したら二度と出ない |
| **トースト** | いま起きたことを言う | 流れて消える。エラーの唯一の置き場にしない |
| **呼びかけの帯**（`#ask`・`.pask`） | 台本がページ上の作業を人に頼む | 一文 · 主ボタン1つ。上辺は `--warn`（人が要る）。盤面がページの下に描き、ページの中には決して描かない＝押せるのは人だけ。台本が下げるまで残る |
| **ボタン** | する | 主＝`--brand` の枠、静か＝`--line` の枠、壊す＝`--stop` の枠。キャンセルと閉じるは静か。色を付けない |

上の表で、いちばんよく破られる2つ:

- **数字を裸で置かない。** `20%` は事実ではない。`20% 使用 · 3時間45分後に回復` が
  事実。数字には必ず名前（何の数か）と、変わるものなら時刻が付く。
- **棒も裸で置かない。** 棒は数字、隣の言葉が文。

## 6. 動き

永久に動くものを置かない。窓の中の滑らかなアニメは、動いている間ずっと1コアの
2割を食います。許すのは `step-end` の点滅2つ。処理中の点と、次に押す1か所の
パルス。開閉は一段で大きさが変わってよい。ページが読めるなら「動きを減らす」の
設定に従う。

## 7. 言葉

決めごとは `.claude/RULES.md`。画面で一番よく滑るところの検査:

- ラベルは名詞（「ここで起動」）、ボタンは動詞（「作る」）、ヒントは「何が起きるか」で、
  「なぜそうしているか」ではない。
- 開発の言葉を画面に出さない。フック、プリミティブ、プロトコル、トークン。worktree は
  製品では「並行開発」で、git の語は括弧で一度だけ。
- 「〜してください（お願い）」「簡単に」「〜できます」「任意」「無視して構いません」を
  書かない。
- コードがやっていないことを言わない。「作りました」「見つけました」「送りました」は
  結果があってから。途中は「何をしているか」を書く。
- 文字はすべて `lang/en.json` から `T[...]` / `t()` で。日本語は `lang/ja.json` に、
  日本語の読者向けに書く（訳さない）。常用漢字だけ。

## 8. 窓とスマホ

盤面のページは窓でもスマホでもあります。どの部品も指で使えること。ホバーでしか
届かないものを置かない、22px より小さい押す物を置かない、メニューはタップで開く。
窓でできることはスマホでもできる。例外は「開く先がこの PC の中」のときだけで、その
ときスマホには素のリンクか何も無いかで、理由をコメントに書く。

## 9. 画面の採点

画面を変えたセッションは、終わる前にスクリーンショットを撮り、この表で採点します。
効き目の大きい直しを3つ先に挙げ、直してから `/announce` に渡します。

**それぞれに答える。「いいえ」は直すことであって、書き残すことではない。**

1. **初見で読める。** この製品を見たことがない人が、画面の言葉と数字を全部分かるか。
   数字には名前が、変わるものには時刻が付いているか。
2. **押す所は1つ。** 主の操作が、位置と `--brand` の枠で一目で分かり、ほかは静かか。
3. **2回で終わる。** よくある道が、1〜2回の操作で終わるか（プログラムが既に十分
   知っているなら）。
4. **フォーカスとキー。** ダイアログで、Enter が主の操作になる場所にフォーカスが
   あり、Esc が静かに戻るか。
5. **状態の色は状態だけ。** 青は注目と完了、緑は作業中、黄は人が要る・残りわずか、
   赤は停止。飾りに使っていないか。
6. **格子。** 行と列がそろい、点が1本の列に並び、比べる数字は右ぞろえか。
7. **言葉。** ラベルは名詞、ボタンは動詞、開発の言葉なし、埋め草なし、やっていない
   ことを言っていない。日本語の段落は `natural-japanese` の検査を通したか。
8. **空と失敗。** まだ何も無いとき、次に押す所を言っているか。失敗したとき、読んで
   直せる場所にエラーが残り、直す先が別なら案内があるか。
9. **兄弟。** 隣の部品と1つの設計に見えるか（同じ大きさ、同じ角丸、同じ行為に同じ言葉）。
10. **両方の配色、両方の面。** 明るい配色でも、スマホ幅で指でも、正しいか。
11. **永久に動くものが無い。**
12. **作り直しに耐える。** 1秒に数回作り直されても、ちらつかず、押し損ねず、開いた
    一覧が状態の到着で閉じないか。

書き方: **直す3つ** · **引っかかり**（要素ごと）· **直したこと** · **残したことと理由**。

## 10. このページが黙っているとき

1. 兄弟の部品にそろえる。同じ流れで隣にあるもの。
2. 周りの見た目にそろえる。いちばん近い面の大きさと言葉。
3. このページの一番近い役割を使い、コメントにそう書く。
4. それでも無ければ、最初に使うのと同じコミットで、ここに役割を足す。
