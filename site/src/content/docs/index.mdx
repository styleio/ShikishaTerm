## Four agents. Four windows. No idea who is waiting.

Running one terminal AI is easy. Running four is not.

You end up with a window per agent, a lot of alt-tabbing to find the one that stopped, and
a lot of copy-pasting between them. The agent that finished ten minutes ago sits there
finished, and you find out when you happen to look.

**SHIKISHA-TERM reads the screen and tells you.** Every tab says whether it is *working*,
*done*, or *waiting for you* — read from what the tool actually printed, so it works with
any CLI rather than one vendor's API.

<img src="/desktop.png" alt="SHIKISHA-TERM — several AI agents in one window, each row showing whether it is working, waiting or done" style="width:100%;border-radius:12px;margin-top:1.2em" />

## The handoff is the work

Knowing who is waiting is half of it. The other half is not being the courier.

Say it once — *when this one finishes, send the result to the review tab* — and it happens
without you. Write it in Lua, or describe it in plain language and let an AI you already
have installed write it for you.

## Agents work in folders, not in a vacuum

An agent that does not know where it is will happily edit the wrong project.

Tabs are grouped by the **working folder** they run in. Give a branch a folder of its own
and the agent working on it stays there. A **git panel** opens where a terminal would:
stage a piece of a file rather than the whole file, read the history from the same panel,
write the commit message yourself or have it written for you, and settle a merge with an
AI untangling it while you decide.

## You are not always at the desk

Scan a QR code and you can see what every tab is doing and send instructions — from the
train, from a café, from bed. Over [Tailscale](https://tailscale.com/) only your own
devices can reach it, encrypted, from anywhere.

## Get started

1. **[Install from the Microsoft Store](https://apps.microsoft.com/detail/9PB8XQVM87Z0)** —
   or unzip the [portable copy](https://github.com/styleio/ShikishaTerm/releases/latest)
   anywhere, including a USB stick.
2. Open it. A terminal tab is already there.
3. Press `[e]`. The settings screen opens **inside the window**, and you pick which AI runs
   in which folder. No JSON to edit.

<img src="/settings.png" alt="SHIKISHA-TERM settings — configure each tab (name, command or SSH host, working folder, automation) in a form, with no JSON editing" style="width:100%;border-radius:12px;margin:.4em 0 1em" />

## Questions people ask first

<details>
<summary><strong>Do I need API keys?</strong></summary>

No. It drives the command-line tools you have already installed and signed in to, using
the subscriptions you already pay for. It stores no keys and asks for none.
</details>

<details>
<summary><strong>Does it replace Claude Code / Codex / Gemini?</strong></summary>

No — it runs them. Your logins, settings and history stay exactly where they are. If a new
CLI comes out tomorrow, point a tab at it.
</details>

<details>
<summary><strong>Windows only?</strong></summary>

Today, yes. It is built on ConPTY, the Windows pseudo-console, rather than on a
cross-platform shim — which is also why SSH, WSL, IME input and legacy encodings behave
the way they do on Windows.
</details>

<details>
<summary><strong>What does it send anywhere?</strong></summary>

By default, nothing. There is no account and no server of ours. Connections happen only
where you set them up, and go straight to the party you chose: the AI provider whose key
you entered, a webhook you registered, or your own phone. The
[privacy policy](/privacy/) lists every one of them.
</details>

<details>
<summary><strong>Is it a terminal or an IDE?</strong></summary>

A terminal. It has a git panel and a browser because agents need them, but it is not
trying to become your editor.
</details>

<details>
<summary><strong>Store copy or portable zip?</strong></summary>

The Store copy is signed by Microsoft, shows no warning and updates itself. The zip is the
same build with nothing installed — unzip it, run it, delete the folder to remove it — but
**Windows will warn about it the first time**, because it is not code-signed. See below for
what that looks like and how it goes away.
</details>

## The warning on the zip, and how you can remove it

The first time you run the unzipped copy, Windows says **"Windows protected your PC"**.
That is SmartScreen, and it is alarming if nobody warned you — so, warning you: it is
expected, and **More info → Run anyway** gets past it. It appears because the zip carries
no code-signing certificate, not because anything is wrong with the file. Every release is
built by public GitHub Actions from a tagged commit, and a SHA256 sits next to the download
so you can check the bytes you got are the bytes that were built.

**The Store copy does not show it at all** — Microsoft signs that one.

Making it disappear from the zip too means a code-signing certificate.
[SignPath Foundation](https://signpath.org/) issues them to open source projects for free,
and for programs like this one they ask for *"a certain verifiable reputation"* before
putting their own name behind a certificate. For a project on GitHub, the most legible form
that reputation takes is stars.

So if this is useful to you: **[star it on GitHub](https://github.com/styleio/ShikishaTerm)**.
It is the one thing a stranger can do in a second that makes a signed build likelier — for
everyone who downloads the zip after you.
